# 3D_VPR_exp

Локализация по 3D-карте маршрута. Улица и тротуары.

Меняет связку «retrieval → ближайший кадр → угол к нему» на «retrieval → PnP по 3D-карте → **поза**». Разница принципиальная: сейчас позицию робота не вычисляет никто, есть только топологический сосед и относительный угол к нему. Отсюда потолок точности.

## Стек

**Офлайн, карта (машина с RTX 3050 12GB):**

| шаг | выбор | почему |
|---|---|---|
| нарезка | 3 fps | при ходьбе ~1.4 м/с даёт шаг ~0.5 м. 30 fps избыточно: 4857 кадров → ~490 |
| маскирование | сегментация: небо, машины, люди | иначе припаркованные машины впекутся в карту как статика |
| фичи | **XFeat** | карта и запрос обязаны нести ОДИН дескриптор. В hloc не штатный, нужен адаптер |
| пары | последовательные + петли по **SALAD** | all-vs-all на сотнях кадров не нужен; для видео правильный матчер — sequential |
| матчинг | **LighterGlue** | НЕ LightGlue: тот обучен под 256-мерные дескрипторы SuperPoint, у XFeat 64 |
| SfM | **GLOMAP** | глобальный: вращения разом → позиции → один BA. На тысячах кадров инкрементальный COLMAP = часы/дни |
| фолбэк | COLMAP incremental | если глобальный не сойдётся |
| выход | sparse-модель (формат COLMAP) + route graph из поз | dense/MVS НЕ нужен: нужны точки с дескрипторами, а не поверхность. Он же и плавит видеокарты |

**Онлайн, Jetson Orin:**

SALAD → top-k → XFeat → LighterGlue → 2D-3D → **pycolmap PnP + RANSAC** → поза → route graph → ошибка поперёк пути и по курсу → `move_type` (left/right/straight).

**Просмотр:** COLMAP GUI (`sudo apt-get install colmap`, 3.9.1). Sparse-облако — тысячи точек, встроенная Iris Xe тянет с запасом.

**Роли модулей:**
- карта + PnP — статика: где я, где путь
- сегментация — динамика (чего в карте нет) + маскирование нестабильного перед картой и запросом

## Масштаба нет, GNSS нет

**Для `move_type` масштаб не нужен.** Порог ошибки поперёк пути калибруется прямо в единицах карты: важно, что при 0.42 условных единиц робот ведёт себя правильно, а не что это 0.3 м. Решение дискретное — знак и порог.

Масштаб понадобится в одном месте: **когда мозг сведёт модуль 2 с модулем 3 в калмане**. Сегментация отдаёт метры, карта — попугаев, складывать нельзя.

Взять его тогда:
1. **одометрия робота** — проехал отрезок, энкодеры дали метры, карта дала единицы, поделил. Само себя уточняет;
2. **рулетка** — один раз померить одну длину на маршруте (ширина тротуара, шаг фонарей), найти её в карте;
3. стандартные размеры (знак 3.1 по ГОСТ, номер 520x112) — от отчаяния, в кадре они мелкие после телеграма.

## Данные

- Снято **с руки, телефоном** (~1.5 м) — на июльском видна тень человека с телефоном. Камера `data/photo`, НЕ камера робота.
- Прошло через **Telegram** (`ftypisom/iso2/avc1`, имя `video_YYYY-MM-DD_HH-MM-SS.mp4`): перекодировано, метаданные срезаны, фокуса в EXIF нет.
- **Портрет** — небо и асфальт занимают большую часть кадра, полезная полоса (здания, столбы, знаки) сжата в середину.

## Калибровка

- **Для карты** — не нужна, GLOMAP/COLMAP самокалибруются.
- **Для робота** — нужна, и она есть (`experiment/camera_intrinsics.npz`, 1280x720 ландшафт). Совпадать должны фичи, а не камеры: cross-device localization — нормальная практика.

## Риски

Четыре сложности штабелем на этом видео:

1. **Движение строго вперёд** — классически трудный случай SfM: точки у точки схода имеют почти нулевой параллакс. Спасают боковые здания.
2. **Самокалибровка при движении по оптической оси** плохо обусловлена для оценки фокуса.
3. **EIS** — если была включена, интринсики плывут покадрово, фиксированного пинхола нет. По метаданным не определить.
4. **Роллинг-шаттер** — телефон + ходьба, COLMAP его не моделирует.

Плюс уличная специфика против офисной:

- **смена внешнего вида во времени** — главный убийца уличного VPR. Июльская карта против январского робота: снег, голые деревья. Лечится семантической фильтрацией и пересъёмкой;
- **динамика в карте** — машины уедут;
- **текстура** — асфальт бедный и самоповторяющийся, небо бесполезно.

## Порядок

**Первый прогон — стоковый SIFT из COLMAP, не XFeat.** Вопрос сейчас: сходится ли SfM на этой съёмке вообще. Это свойство видео, а не фич. Если не сойдётся на SIFT — на XFeat тем более, и адаптер к hloc окажется выброшенным временем.

`scripts/build_map.py` — нарезка + feature_extractor + sequential_matcher + GLOMAP.

GLOMAP на pypi нет, собирается из исходников (github.com/colmap/glomap) на машине с 3050.

Сойдётся → меняем SIFT на XFeat, добавляем SALAD, строим route graph.
Не сойдётся → переснимаем камерой робота: ландшафт, змейкой вместо прямой.
