# Runtime-шарды и веб-админка Jetson

## Готовые карты и шарды

Полная передняя карта маршрута 1–2 разделена на семь частей с перекрытием по 25
узлов с каждой стороны:

```text
route12_front_runtime_01_of_07 ... route12_front_runtime_07_of_07
route12_front_runtime_manifest.json
```

Полная задняя карта маршрута 3 разделена на три части:

```text
route3_rear_runtime_01_of_03 ... route3_rear_runtime_03_of_03
route3_rear_runtime_manifest.json
```

Основные диапазоны равны. Перекрытие входит в оба соседних шарда, чтобы
локализация не терялась непосредственно на границе. Внутри каждого каталога:

```text
runtime.npz       # только позы и 3D-точки диапазона
aliked_bank.npz   # только дескрипторы этих 3D-точек, owner переиндексирован
shard.json        # глобальные/core/local границы
```

`core_global_start/stop` — неперекрывающийся основной диапазон. Фактически
загруженный диапазон — `global_node_start/stop`. Переключаться на следующий
шард следует до выхода из core, находясь в общей зоне двух шардов.

Создание повторяется командой:

```bash
.venv/bin/python -m module2_localization.tools.shard_runtime_map \
  --map route12_front_colmap_full_1701_fullopencv_cpu10_final \
  --parts 7 --overlap-nodes 25 --prefix route12_front_runtime

.venv/bin/python -m module2_localization.tools.shard_runtime_map \
  --map route3_rear_gap8_final \
  --parts 3 --overlap-nodes 25 --prefix route3_rear_runtime
```

Нельзя нарезать только маршрут в `runtime.npz`, оставив полный descriptor bank:
скорость не изменится. Инструмент распределяет точки по ближайшему узлу,
фильтрует дескрипторы и заново нумерует `owner`.

## Ручное и автоматическое переключение

При `SHARD_PRELOAD_ALL=True` демон на старте загружает в память все семь шардов
маршрута 1-2 и все три шарда маршрута 3. Во время движения диск не используется:
на каждом кадре работает только активный локализатор, а в перекрытии дополнительно
проверяется следующий. Поэтому переключение не ждёт загрузки карты.

В админке маршрут выбирается целиком: `Маршрут 1-2` включает ведущую переднюю
цепочку, `Маршрут 3` — готовую заднюю цепочку. Команда NATS имеет вид
`{"cmd":"set_route","route":"route12"}` или `route3`.

Ручное переключение реализовано. Админка обнаруживает все каталоги, содержащие
одновременно `runtime.npz` и `aliked_bank.npz`, делит их на front/rear и
показывает полные карты и шарды. Команда имеет вид:

```json
{"cmd":"set_map","camera":"front","map":"route12_front_runtime_02_of_07"}
```

Во время ручной загрузки старая карта продолжает вести робота. После полной
загрузки ссылка на локализатор заменяется атомарно, состояние pause/resume
сохраняется, повторный `СТАРТ` не требуется. Телеметрия содержит имя `map`,
локальный `node` и `global_node`, вычисленный из `shard.json`.

Автоматическая предзагрузка реализована менеджером `ShardedLocalizer`:

1. стартовая локализация идёт по первому или вручную выбранному шарду;
2. за 25 глобальных узлов до core-границы следующий банк загружается в фоне;
3. текущий банк всё это время продолжает выдавать команды;
4. новый шард должен дать минимум два уверенных фикса и согласовать глобальный
   узел с текущим с погрешностью не больше 25 узлов;
5. на core-границе активная ссылка заменяется атомарно;
6. Pilot сохраняет состояние pause/resume, остановки и повторного старта нет;
7. цепочка движется только вперёд A→B; одиночный обратный скачок PnP не может
   запустить загрузку старого шарда.

При старте загружаются все десять шардов обоих маршрутов. В вычислениях участвует
только активный шард, а в переходной зоне — активный и следующий.

## Веб-админка

Админка запускается на Jetson рядом с NATS и сервисом локализации:

```bash
.venv/bin/python -m module2_localization.admin \
  --bind 0.0.0.0 --port 8080 \
  --nats-url nats://127.0.0.1:4222
```

После подключения ноутбука или телефона к точке доступа Jetson открыть:

```text
http://IP_ДЖЕТСОНА:8080/
```

Например, если Jetson в точке доступа имеет `192.168.4.1`:

```text
http://192.168.4.1:8080/
```

Страница показывает:

- облако и эталонную линию активной карты;
- текущую позицию и направление;
- команду, угол, узел, отклонение и inliers;
- режим и активную камеру;
- наличие NATS и возраст последней телеметрии.
- список полных карт и шардов с глобальными диапазонами;
- карту, фактически указанную сервисом в текущей телеметрии.

Кнопки публикуют те же команды, что раньше отправлял `viz.py` с клавиатуры:

- `СТАРТ` → `resume`;
- `ПАУЗА` → `pause`;
- `СБРОС` → `reset`;
- `REAR` → `set_mode: rear`;
- `DUAL` → `set_mode: dual`.
- выбор `front/rear` + карты → `set_map`.
- `СВЕТОФОР ON/OFF` → runtime-команда `set_traffic`; перезапуск сервиса не нужен.

По умолчанию `NAV_MODE = "dual"`, активна передняя камера. На данный момент
полная front-карта относится к маршруту 1–2, а готовая rear — к маршруту 3.
Это не совместимая dual-пара. При потере front сервис безопасно выдаёт `STOP`
с `map_mismatch`, а не пытается рулить по чужому маршруту. Резерв заработает
после выбора rear-карты того же маршрута.

## Светофорные зоны и шарды

Зоны задаются в `config.TRAFFIC_ZONES` по имени карты и в глобальных узлах.
`global_node` остаётся единым при переключении шардов. Если карты нет в словаре,
детектор светофора на ней не активируется. Это принципиально: прежнее значение
`None` трактовалось как «вся карта» и могло остановить робота вне перехода.

При смене карты светофорная машина состояний сбрасывается в `WAIT_RED`. Для нового
front-маршрута COLMAP `image_id 870..880` сопоставлен с глобальными runtime-узлами
`869..879`. Для rear route3 указанный пользователем диапазон зафиксирован как
глобальные навигационные узлы `410..430` (DB image_id 410 в этой модели отсутствует).

Автомат светофора намеренно консервативен:

```text
въезд в зону -> WAIT_RED
первым увидели GREEN -> остаёмся WAIT_RED и стоим
увидели RED -> WAIT_GREEN и стоим
после RED увидели GREEN -> GO
GO -> едем, детектор больше не запускается до явного reset или повторного ON
```

`GO` является маршрутной защёлкой: последующий красный, медленный проезд или
дрожание узла уже не могут остановить робота посреди дороги. Это исключает и
выезд на зелёный, для которого неизвестно оставшееся время. При
выключении детекции в админке светофорная ветка немедленно перестаёт блокировать
навигационную команду. При повторном включении автомат начинает заново с
`WAIT_RED`. Модели при первом включении загружаются лениво в фоне; текущая карта
продолжает вести робота.

Админка не управляет моторами напрямую. Она публикует JSON в
`robot.vision.control`, а `service.py` применяет команду. Это сохраняет один
контрольный интерфейс для GUI, сайта и будущей автоматики.

## Сеть и безопасность

`--bind 0.0.0.0` делает сайт доступным на всех интерфейсах Jetson. В текущей
версии авторизации нет, поэтому порт 8080 следует открывать только в доверенной
локальной сети точки доступа и не пробрасывать в интернет. NATS также не должен
быть доступен из недоверенной сети без авторизации.

## Проверка

1. Запустить NATS.
2. Запустить `module2_localization.service`.
3. Запустить `module2_localization.admin`.
4. Открыть сайт по IP Jetson.
5. Нажать `ПАУЗА`: команда должна стать `STOP`, появиться `paused`.
6. Нажать `СТАРТ`: локализация продолжится.
7. Отключить сервис: индикатор возраста телеметрии должен стать красным.

Локальный end-to-end тест HTTP + NATS выполнен: страница, status API и публикация
`pause` работают.
