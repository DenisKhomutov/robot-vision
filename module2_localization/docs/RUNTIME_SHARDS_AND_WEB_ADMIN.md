# Runtime-шарды и веб-админка Jetson

## Готовые карты и шарды

Полная передняя карта маршрута 1–2 разделена на семь частей с перекрытием по 25
узлов с каждой стороны:

```text
route12_front_runtime_01_of_07 ... route12_front_runtime_07_of_07
route12_front_runtime_manifest.json
```

Полная задняя карта маршрута 3 разделена на три части:

```text
route3_rear_runtime_01_of_03 ... route3_rear_runtime_03_of_03
route3_rear_runtime_manifest.json
```

Основные диапазоны равны. Перекрытие входит в оба соседних шарда, чтобы
локализация не терялась непосредственно на границе. Внутри каждого каталога:

```text
runtime.npz       # только позы и 3D-точки диапазона
aliked_bank.npz   # только дескрипторы этих 3D-точек, owner переиндексирован
shard.json        # глобальные/core/local границы
```

`core_global_start/stop` — неперекрывающийся основной диапазон. Фактически
загруженный диапазон — `global_node_start/stop`. Переключаться на следующий
шард следует до выхода из core, находясь в общей зоне двух шардов.

Создание повторяется командой:

```bash
.venv/bin/python -m module2_localization.tools.shard_runtime_map \
  --map route12_front_colmap_full_1701_fullopencv_cpu10_final \
  --parts 7 --overlap-nodes 25 --prefix route12_front_runtime

.venv/bin/python -m module2_localization.tools.shard_runtime_map \
  --map route3_rear_gap8_final \
  --parts 3 --overlap-nodes 25 --prefix route3_rear_runtime
```

Нельзя нарезать только маршрут в `runtime.npz`, оставив полный descriptor bank:
скорость не изменится. Инструмент распределяет точки по ближайшему узлу,
фильтрует дескрипторы и заново нумерует `owner`.

## Состояние автоматического переключения

На момент создания документа `service.py` загружает один `AlikedLocalizer` и не
переключает шарды автоматически. Файлы готовы, но для использования требуется
менеджер шардов:

1. стартовая локализация по первому или выбранному шарду;
2. предзагрузка следующего банка в зоне перекрытия;
3. несколько уверенных фиксов следующего шарда;
4. атомарное переключение активного локализатора;
5. освобождение GPU-памяти предыдущего банка;
6. обратное переключение при движении назад;
7. сохранение глобального номера узла через данные `shard.json`.

Нельзя синхронно грузить банк ровно на последнем core-узле: это создаст паузу в
командах. Также нельзя одновременно держать все десять банков на Jetson.

## Веб-админка

Админка запускается на Jetson рядом с NATS и сервисом локализации:

```bash
.venv/bin/python -m module2_localization.admin \
  --bind 0.0.0.0 --port 8080 \
  --nats-url nats://127.0.0.1:4222
```

После подключения ноутбука или телефона к точке доступа Jetson открыть:

```text
http://IP_ДЖЕТСОНА:8080/
```

Например, если Jetson в точке доступа имеет `192.168.4.1`:

```text
http://192.168.4.1:8080/
```

Страница показывает:

- облако и эталонную линию активной карты;
- текущую позицию и направление;
- команду, угол, узел, отклонение и inliers;
- режим и активную камеру;
- наличие NATS и возраст последней телеметрии.

Кнопки публикуют те же команды, что раньше отправлял `viz.py` с клавиатуры:

- `СТАРТ` → `resume`;
- `ПАУЗА` → `pause`;
- `СБРОС` → `reset`;
- `REAR` → `set_mode: rear`;
- `DUAL` → `set_mode: dual`.

Админка не управляет моторами напрямую. Она публикует JSON в
`robot.vision.control`, а `service.py` применяет команду. Это сохраняет один
контрольный интерфейс для GUI, сайта и будущей автоматики.

## Сеть и безопасность

`--bind 0.0.0.0` делает сайт доступным на всех интерфейсах Jetson. В текущей
версии авторизации нет, поэтому порт 8080 следует открывать только в доверенной
локальной сети точки доступа и не пробрасывать в интернет. NATS также не должен
быть доступен из недоверенной сети без авторизации.

## Проверка

1. Запустить NATS.
2. Запустить `module2_localization.service`.
3. Запустить `module2_localization.admin`.
4. Открыть сайт по IP Jetson.
5. Нажать `ПАУЗА`: команда должна стать `STOP`, появиться `paused`.
6. Нажать `СТАРТ`: локализация продолжится.
7. Отключить сервис: индикатор возраста телеметрии должен стать красным.

Локальный end-to-end тест HTTP + NATS выполнен: страница, status API и публикация
`pause` работают.
