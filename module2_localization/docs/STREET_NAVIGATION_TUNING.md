# Настройка упреждения уличной навигации

## Актуальные runtime-карты

Основные front-цепочки `1-2`, `2-1` и `3-1` содержат по 25 шардов. Маршрут `2`
использует заднюю цепочку из 10 шардов. Это карты разных маршрутов, поэтому их
нельзя объединять в `dual` как front/rear-пару. Для двухкамерной страховки нужны
две карты одного физического проезда.

Ниже приведены значения, фактически установленные в `module2_localization/config.py`.

```python
NAV_LAG_S = 0.08
NAV_LAG_ADAPTIVE = False
NAV_LEAD_MAX = 0.08
NAV_LEAD_SMOOTH = 7

STEER_MODE = "pursuit"
LOOKAHEAD_NODES = 5
LOOKAHEAD_MIN = 4
LOOKAHEAD_ADAPT = 30.0
LOOKAHEAD_SPEED_DIV = 13.0
LOOKAHEAD_MAX = 20.0
```

## Какие механизмы упреждения используются

Работают два независимых механизма.

### 1. Компенсация задержки локализации

Локализатор оценивает скорость по истории поз и переносит расчётную позицию вперёд по курсу.

- `NAV_LAG_S` — время, на которое виртуальная поза продвигается вперёд.
- `NAV_LEAD_MAX` — предельный пространственный сдвиг. Защищает от выброса оценки скорости.
- `NAV_LEAD_SMOOTH` — размер окна оценки скорости. Большее значение даёт более гладкую, но
  более инертную оценку.
- `NAV_LAG_ADAPTIVE` — при `True` вместо постоянного `NAV_LAG_S` используется измеренное время
  обработки текущего кадра. Для проверенной конфигурации оставлено `False`, чтобы команды не
  менялись из-за колебаний времени инференса.

### 2. Адаптивная точка прицеливания Pure Pursuit

Если в `gateway.robot.speed` получен `speed_pwm`, базовое упреждение равно
`clamp(speed_pwm / 13, 4, 20)` узлов. Без сообщения скорости используется
`LOOKAHEAD_NODES = 5`. При боковом отклонении Pure Pursuit дополнительно сокращает
прицеливание с силой `LOOKAHEAD_ADAPT`, но не ниже `LOOKAHEAD_MIN = 4`.

## Что менять при испытаниях

Менять параметры следует по одному, начиная с `LOOKAHEAD_NODES`.

Если робот срезает повороты или стремится на траву:

```text
LOOKAHEAD_NODES: 5 -> 4
LOOKAHEAD_MIN:    4 -> 3
NAV_LAG_S:        0.08 -> 0.05
NAV_LEAD_MAX:     0.08 -> 0.05
```

Главный параметр против срезания — `LOOKAHEAD_NODES`. Сначала следует менять только его.

Если робот начинает вилять:

```text
LOOKAHEAD_NODES: 5 -> 7 -> 9
LOOKAHEAD_MIN:    4 -> 5
NAV_LEAD_SMOOTH:  7 -> 9
```

Если команды запаздывают:

```text
NAV_LAG_S: 0.08 -> 0.10 -> 0.12
```

Если команды слишком резко реагируют на небольшое отклонение:

```text
LOOKAHEAD_ADAPT: 30 -> 20
```

Если робот недостаточно быстро возвращается к линии:

```text
LOOKAHEAD_ADAPT: 30 -> 40
LOOKAHEAD_MIN:    4 -> 3
```

## Важное ограничение текущей формулы

`LOOKAHEAD_NODES` задаётся в узлах, а боковое отклонение в текущей реализации измеряется в
единицах масштаба карты. Поэтому `LOOKAHEAD_ADAPT = 30` практически проверен именно на текущей
карте и может потребовать настройки на карте другого масштаба.

Для полной переносимости следует в будущем сначала переводить боковое отклонение в число шагов
маршрута (`abs(offset) / node_step`), а уже затем сокращать упреждение в узлах. До такой правки
проверенные параметры выше являются основной уличной конфигурацией.

## Исправление залипания команды

`NavigationCommandFilter` считает изменение ближайшего узла маршрута самостоятельным признаком движения.
Это устраняет случай, когда плотная карта давала перемещение меньше `MOVE_EPS`, робот ошибочно
считался стоящим и первая команда поворота повторялась бесконечно.
