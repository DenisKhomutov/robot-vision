# Практическая сборка уличной COLMAP-карты

## Подтверждённый результат

Рабочая карта маршрута 3 собрана из задней монокулярной камеры:

- 574 зарегистрированные позы;
- 119 461 исходная 3D-точка;
- средняя ошибка репроекции 1,133 px;
- после runtime-очистки осталось 100 892 точек;
- рабочая модель не имеет наблюдавшегося ранее накопительного сжатия масштаба;
- при расширении полной карты RMS-деформация ранее принятой части составила
  0,049% от размера карты.

Главный практический вывод: причиной сильного дрейфа была адаптивная нарезка по
полному optical flow. На поворотах вращение камеры ошибочно воспринималось как
полезный параллакс, поэтому сохранялось до 15 кадров в секунду с почти нулевой
трансляционной базой. Равномерный шаг по исходному видео устранил этот режим.

## Обязательные правила

1. Для улицы использовать фиксированный шаг 8 исходных кадров при 30 FPS
   (примерно 3,75 FPS).
2. Не учащать выборку на поворотах. Большой пиксельный flow от yaw не означает
   хороший параллакс.
3. Стоянки исключать. Кадр принимается только после накопления заметного
   движения относительно последнего сохранённого кадра.
4. Не использовать маски динамических объектов по умолчанию. В проверенном
   маршруте маски уменьшали и без того слабую геометрическую связность.
5. Использовать COLMAP incremental mapper, SIMPLE_RADIAL и разрешать уточнение
   фокуса и одного radial-параметра.
6. Выполнять настоящую глобальную BA примерно каждые 100 новых камер.
7. Двухкадровые точки разрешать во время реконструкции, иначе сложные участки
   могут не зарегистрироваться.
8. После готовой BA создавать отдельную navigation-копию и удалять из неё точки
   с длиной трека меньше 3. Исходную SfM-модель не перезаписывать.
9. Всегда сохранять отдельную предыдущую принятую карту перед расширением.
10. Масштаб проверять по объектам сцены. Расстояние между позами зависит от
    скорости робота и само по себе не доказывает дрейф.

## Что не сработало

- адаптивная нарезка `shift=22/40`: на поворотах создаёт слишком плотные кадры;
- GLOMAP для этого маршрута: давал худшую геометрию;
- маски людей и машин: ослабляли связность;
- фиксирование старых поз и добавление по 1/10 камер: консервировало ошибочную
  глубину, но не переносило масштаб;
- rolling/fixed anchor и Sim(3)-слияние блоков: дрейф передавался новым блокам;
- motion prior: ломал траекторию;
- жёсткий угол триангуляции 3°: подтверждал слабый параллакс, но оставлял на
  некоторых участках только 39–50 опорных точек;
- радикальный выбор только кадров с параллаксом ≥1°: оставил 64 кадра и потерял
  цепочку инициализации;
- удаление двухкадровых точек до mapper: может разорвать регистрацию.

## 1. Нарезка видео

Из корня проекта:

```bash
uv run --no-sync python -m module2_localization.tools.extract_adaptive \
  module2_localization/data/street_video/VIDEO.mkv \
  --out frames_ROUTE_CAMERA_gap8_nomask \
  --fixed-gap 8 \
  --min-move 2
```

`--fixed-gap 8` запрещает раннее сохранение кадров на поворотах. Если робот
стоит, якорный кадр не сбрасывается: движение должно накопиться относительно
последнего принятого изображения.

После нарезки проверить `extraction.json`:

```json
{
  "fixed_gap": 8,
  "min_gap": 8,
  "max_gap": 8
}
```

## 2. Признаки и соответствия

Для новой карты признаки и LightGlue-соответствия считаются один раз:

```bash
uv run --no-sync python -m module2_localization.tools.build_map \
  --images frames_ROUTE_CAMERA_gap8_nomask \
  --tag map_ROUTE_CAMERA_gap8 \
  --mapper colmap \
  --pairs sequential \
  --overlap 25 \
  --det-threshold 0.04 \
  --refine-intrinsics \
  --colors
```

Для длинной уличной карты нужны пары последовательных кадров с перекрытием 25.
Схемы `1,3,6,10`, exhaustive и vocabulary tree не лечат слабый параллакс.

Внимание: `build_map.py` также запускает mapper. Для эталонной уличной сборки
проверить итоговую команду в логе. Рекомендуемые параметры mapper:

```bash
colmap mapper \
  --database_path MAP/database.db \
  --image_path IMAGE_DIR \
  --output_path MAP/sparse \
  --Mapper.multiple_models 0 \
  --Mapper.extract_colors 1 \
  --Mapper.ba_refine_focal_length 1 \
  --Mapper.ba_refine_principal_point 0 \
  --Mapper.ba_refine_extra_params 1 \
  --Mapper.tri_ignore_two_view_tracks 0 \
  --Mapper.tri_min_angle 1.5 \
  --Mapper.filter_min_tri_angle 1.5 \
  --Mapper.local_ba_min_tri_angle 6 \
  --Mapper.ba_global_images_freq 100 \
  --Mapper.ba_global_points_freq 50000 \
  --Mapper.ba_global_max_num_iterations 100 \
  --Mapper.ba_global_max_refinements 10
```

На машине с доступной CUDA можно добавить:

```bash
--Mapper.ba_use_gpu 1 --Mapper.ba_gpu_index 0
```

GPU ускоряет BA, но не меняет геометрию и не лечит масштаб.

## 3. Контроль результата

```bash
colmap model_analyzer --path MAP/sparse/0
```

Проверить:

- зарегистрировано не меньше 95% выбранных движущихся кадров;
- нет разрывов траектории;
- reprojection error ориентировочно 1–1,5 px;
- фокус не уходит к физически невозможному значению;
- люди, заборы, стены и плоскость дороги сохраняют размер по маршруту;
- высота камеры визуально соответствует реальным 0,87 м.

Незарегистрированные кадры длительной стоянки не добавлять принудительно.

## 4. Runtime-очистка

Сначала окрасить полную модель, если mapper строился без цветов:

```bash
mkdir -p MAP/viewer_model_colored
colmap color_extractor \
  --image_path IMAGE_DIR \
  --input_path MAP/sparse/0 \
  --output_path MAP/viewer_model_colored
```

Создать отдельную navigation-копию:

```bash
uv run --no-sync python -m module2_localization.tools.clean_colmap_model \
  --input MAP/viewer_model_colored \
  --output MAP/viewer_model_clean \
  --min-track-length 3 \
  --min-retained-ratio 0.70 \
  --absolute-image-root IMAGE_DIR
```

Затем descriptor bank и runtime-экспорт строятся из очищенной модели. Не
удалять автоматически треки длины 3–4: на слабых уличных участках они полезны.

## 5. Расширение существующей карты

1. Новые изображения выбирать тем же фиксированным шагом 8.
2. Сохранить предыдущую карту отдельным каталогом.
3. Запустить mapper с `--input_path` на предыдущую `sparse`-модель.
4. Передать `image_list_path`, содержащий старые и новые выбранные кадры.
5. Не фиксировать старые камеры: глобальная BA должна согласовать всю модель.
6. После сборки выровнять старую и новую модели одним Sim(3) и проверить RMS
   изменения общей части. Практически полученные значения 0,008–0,049% были
   безопасными.
7. Принять расширение только после визуальной проверки масштаба.

## Финальная карта маршрута 3

```text
module2_localization/maps/route3_rear_colmap_forward/
├── database.db
├── pairs.txt
└── fixed_gap8_complete/
    ├── images.txt
    ├── sparse/
    ├── viewer_model_colored/
    └── viewer_model_clean/
```

`viewer_model_clean` — предпочтительная модель для навигационного банка.
`sparse` — полная исходная реконструкция и резерв для повторной фильтрации.

Перед runtime-экспортом очищенную модель следует поместить в отдельный каталог
карты со стандартной структурой `sparse/0`. Нельзя смешивать `runtime.npz` от
полной модели и descriptor bank от очищенной: индексы 3D-точек различаются.
