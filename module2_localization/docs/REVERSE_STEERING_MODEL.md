# Корректное управление рулём при движении назад

## Текущее подтверждённое поведение

Полевые тесты подтвердили актуальную модель заднего хода: при движении назад
физический угол передних колёс должен быть противоположен повороту корпуса.
Если корпус должен уходить налево, колёса должны повернуться вправо; если корпус
должен уходить направо, колёса должны повернуться влево.

Сейчас после расчёта ошибки относительно задней оси применяется симметричная
инверсия команды:

```text
left     -> right
right    -> left
straight -> straight
```

Это не точечная защита конкретного манёвра, а текущая рабочая runtime-модель
заднего хода.

## Почему нужна именно инверсия

Необходимо различать:

- направление прохождения траектории;
- направление поворота корпуса;
- физический угол передних колёс;
- выбранную передачу: вперёд или назад.

При движении вперёд направление поворота траектории и знак рулевого угла
совпадают. При движении назад для одинакового поворота корпуса знак физического
угла колёс меняется.

Команды `left` и `right` в NATS-контракте трактуются как физическое направление
руления колёс. Поэтому в backward-режиме знак после расчёта задней оси
инвертируется.

## Более чистый контракт на будущее

Передачу и физический угол руля следует публиковать независимо:

```json
{
  "direction": "backward",
  "steering_deg": 12.0
}
```

Рекомендуемое соглашение:

```text
steering_deg > 0  — колёса вправо
steering_deg < 0  — колёса влево
steering_deg = 0  — колёса прямо
```

Поле `move_type` сейчас остаётся основным для совместимости. В будущем
исполнитель лучше перевести на однозначный физический `steering_deg`.

## Математическая модель

Пусть:

- `body_heading` — направление корпуса робота;
- `direction_sign = +1` для движения вперёд;
- `direction_sign = -1` для движения назад;
- `wheelbase` — колёсная база;
- `curvature` — требуемая кривизна траектории в направлении движения.

Направление движения:

```python
motion_heading = body_heading
if direction == "backward":
    motion_heading = wrap(body_heading + 180.0)
```

После вычисления ошибки относительно `motion_heading` контроллер Pure Pursuit или Stanley получает требуемую кривизну. Физический угол колёс рассчитывается с учётом знака скорости:

```python
steering_rad = atan(direction_sign * wheelbase * curvature)
steering_deg = degrees(steering_rad)
steering_deg = clamp(steering_deg, -max_steering_deg, max_steering_deg)
```

Ограничение должно уменьшать только величину угла и всегда сохранять его знак.

Для заднего хода результат должен быть симметричным:

```text
траектория поворачивает налево  -> колёса вправо
траектория поворачивает вправо  -> колёса влево
траектория идёт прямо           -> колёса прямо
```

## Калибровка исполнительного механизма

Знак конкретного сервопривода задаётся один раз на границе с исполнительным контроллером:

```python
servo_command = STEERING_SIGN * steering_deg
```

`STEERING_SIGN` определяется коротким статическим тестом:

1. Поднять ведущие колёса или исключить движение робота.
2. Отправить небольшой положительный угол.
3. Убедиться, что колёса физически повернулись вправо.
4. Если они повернулись влево, изменить `STEERING_SIGN` с `+1` на `-1`.

Маршрутная логика не должна исправлять полярность конкретного привода.

## Безопасная миграция

Текущую подтверждённую backward-инверсию нельзя менять без отдельного полевого
теста.

Порядок перехода:

1. Сохранить существующие `move_type`, `deg` и зоны заднего хода.
2. Параллельно вычислять новые поля `steering_deg_raw` и `steering_deg` без передачи их приводу.
3. Записать оба результата на прогоне первого и последнего видео 2-1.
4. Сравнить новый физический угол с подтверждёнными командами текущего контроллера.
5. Проверить вперёд, назад-прямо, назад-влево и назад-вправо на вывешенных колёсах.
6. Провести короткий полевой тест на малой скорости с аварийной остановкой.
7. Только после подтверждения переключить исполнитель на `steering_deg`.

## Критерии готовности

Новый контроллер принимается, если:

- передний ход не изменился;
- задний ход прямо выдаёт нулевой угол;
- задний поворот корпуса налево выдаёт колёса вправо;
- задний поворот корпуса вправо выдаёт колёса влево;
- знак не зависит от номера шарда;
- ограничение угла не превращает поворот в `straight`;
- `stop` и `lost` всегда имеют приоритет над рулевой командой;
- результаты одинаковы в видеопрогоне и в runtime-демоне.

## Статус

Текущая симметричная backward-инверсия подтверждена полевым тестом. Она должна
оставаться активной до реализации и физической проверки контроллера с раздельными
`direction` и `steering_deg`.
